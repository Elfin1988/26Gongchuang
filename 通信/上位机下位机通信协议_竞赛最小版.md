# 上位机下位机通信协议（竞赛最小版）

## 1. 文档目的

本文档用于给本项目竞赛小车提供一套“先能稳定跑起来”的最小通信协议。

这一版只保留当前最该实现的内容：

- 上位机能够可靠控制下位机
- 下位机能够返回执行结果
- 底盘和执行机构具备基本安全保护
- 协议足够简单，便于 STM32 和上位机尽快联调

这一版刻意不做以下内容：

- `SRC/DST` 地址体系
- 主动 `EVENT_REPORT`
- `GET_STATUS`
- `GET_RPM`
- `HOME`
- `SET_TARGET`
- 多下位机、广播、参数持久化等扩展能力

如果后续比赛结束或系统趋于稳定，再从完整版协议中逐步补回。

## 2. 设计原则

### 2.1 只做设备控制

本协议只负责设备控制，不负责“取物”“放物”“前往目标点”这类复合动作。
这些任务流程应放在上位机实现。

### 2.2 统一接口风格

当前所有模块只保留以下几类控制：

- `SET_xxx`：设置目标输出或目标状态
- `STOP`：停止模块动作
- `ESTOP`：系统总急停

### 2.3 参数化控制

尽量使用明确参数，而不是单字符指令。

例如：

- 底盘使用 `vx / vy / wz`
- 步进使用 `axis_mask / direction / speed`
- 舵机使用 `servo_id / angle / duration`

### 2.4 可靠执行

所有关键控制命令都建议带应答，至少返回：

- 是否收到
- 是否执行成功
- 如果失败，失败原因是什么

## 3. 物理链路与基础约定

### 3.1 通信链路

- 物理接口：`USART1`
- 波特率：`115200`
- 数据格式：`8N1`

### 3.2 字节序

多字节整数统一使用小端序。

### 3.3 数据类型

| 类型 | 长度 | 说明 |
| --- | --- | --- |
| `u8` | 1 字节 | 无符号 8 位整数 |
| `u16` | 2 字节 | 无符号 16 位整数 |
| `s16` | 2 字节 | 有符号 16 位整数 |
| `s32` | 4 字节 | 有符号 32 位整数 |

### 3.4 单位约定

- 角度：`0.1 deg`
- 线速度：`mm/s`
- 角速度：`0.1 deg/s`
- 步进位置：步数
- 时间：`ms`
- PWM 命令值：`0~100`

补充说明：

- 当前底盘若内部仍按 PWM 控制，实现上可以继续用 PWM
- 但协议层仍建议用速度语义，便于上位机统一控制

## 4. 最小数据帧格式

### 4.1 帧结构

每一帧采用如下格式：

| 字段 | 长度 | 说明 |
| --- | --- | --- |
| `SOF1` | 1 | 帧头 1，固定 `0xAA` |
| `SOF2` | 1 | 帧头 2，固定 `0x55` |
| `FLAGS` | 1 | 标志位 |
| `SEQ` | 1 | 流水号 |
| `MODULE` | 1 | 模块号 |
| `CMD` | 1 | 命令号 |
| `LEN` | 1 | 载荷长度 |
| `PAYLOAD` | `LEN` | 载荷数据 |
| `CRC16` | 2 | CRC16 校验，低字节在前 |

### 4.2 `FLAGS` 定义

| 位 | 名称 | 说明 |
| --- | --- | --- |
| bit0 | `need_ack` | 1 表示该请求需要应答 |
| bit1 | `is_response` | 1 表示该帧是应答帧 |
| bit2 | `is_error` | 1 表示该帧是错误应答 |
| bit3 | `is_event` | 1 表示该帧是主动上报事件 |
| bit4~bit7 | 保留 | 当前固定为 0 |

说明：

- 当前竞赛版已经补充支持少量必要的主动事件上报
- 当前第一项事件上报为“底盘四轮 FG 转速上报”

### 4.3 `SEQ` 规则

- 上位机发请求时自增
- 下位机应答时原样带回
- 用于匹配请求与应答

### 4.4 CRC 规则

推荐使用 `CRC16-MODBUS`：

- 多项式：`0xA001`
- 初值：`0xFFFF`

CRC 计算范围：

- 从 `FLAGS` 开始
- 到 `PAYLOAD` 结束
- 不包含 `SOF1`、`SOF2`
- 不包含 `CRC16` 本身

## 5. 消息类型

### 5.1 请求帧

由上位机发送给下位机。

特征：

- `is_response = 0`

### 5.2 应答帧

由下位机回复请求帧。

特征：

- `is_response = 1`
- `SEQ` 与请求帧相同
- `MODULE` 与请求帧相同
- `CMD` 与请求帧相同

### 5.3 通用应答载荷格式

为了让上位机能直接知道“哪条命令成功了”或“哪条命令失败了”，
本项目当前实现约定所有结果应答统一使用以下载荷格式：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `result` | `u8` | 结果码 |
| `request_module` | `u8` | 对应请求的模块号 |
| `request_cmd` | `u8` | 对应请求的命令号 |

补充说明：

- 虽然应答帧头里的 `MODULE`、`CMD` 本身就会带回原请求值
- 但当前实现仍额外把 `request_module`、`request_cmd` 放入载荷
- 这样上位机调试时，不看帧头也能直接从应答载荷判断是哪条命令的结果

### 5.4 事件上报帧

由下位机主动发送给上位机。

特征：

- `is_response = 0`
- `is_event = 1`
- 不对应某一条请求，因此 `SEQ` 当前固定为 `0`

当前仅定义一种事件：

- 底盘四轮 FG 转速上报

## 6. 模块号定义

延续完整版协议的模块编号，避免后续扩展时重新改号。

| 模块 | 模块号 |
| --- | --- |
| 系统 | `0x00` |
| 底盘电机 | `0x10` |
| 步进电机 | `0x20` |
| 舵机 | `0x30` |

| 摩擦带电机 | `0x50` |
| 运送电机 | `0x60` |

## 7. 结果码定义

所有应答载荷建议以 `result` 开头。

| 结果码 | 名称 | 说明 |
| --- | --- | --- |
| `0x00` | `OK` | 成功 |
| `0x01` | `BAD_LEN` | 载荷长度错误 |
| `0x02` | `BAD_PARAM` | 参数非法 |
| `0x03` | `BUSY` | 模块忙 |
| `0x04` | `TIMEOUT` | 执行超时 |
| `0x05` | `UNSUPPORTED` | 不支持的命令 |
| `0x06` | `CRC_ERROR` | 校验错误 |
| `0x07` | `ESTOP_ACTIVE` | 急停激活中 |
| `0x08` | `DEVICE_FAULT` | 设备故障 |

### 8.2.3 `EVENT_RPM_REPORT`

这是下位机主动发送的事件帧，不是对请求的应答。

帧头特征：

- `FLAGS.is_event = 1`
- `MODULE = 0x10`
- `CMD = 0x81`
- `SEQ = 0x00`

上报周期：

- 当前实现为每 `50 ms` 上报一次，即 `20 Hz`

载荷定义：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `fl_rpm` | `u16` | 前左轮 FG 计算转速 |
| `fr_rpm` | `u16` | 前右轮 FG 计算转速 |
| `rl_rpm` | `u16` | 后左轮 FG 计算转速 |
| `rr_rpm` | `u16` | 后右轮 FG 计算转速 |

补充说明：

- 4 个转速字段均为小端序
- 这是独立事件通道，建议上位机不要把它混进普通命令应答队列
- 这类数据适合画速度趋势图
- 若闭环控制效果不够稳定，后续可以再把上报频率提高到 `50 Hz`

## 9. 超时策略

### 9.1 底盘

- `SET_VELOCITY` 必须带 `timeout_ms`
- 若在超时时间内未收到新的速度命令，下位机自动停车

### 9.2 抽气与运送

- 建议支持 `timeout_ms`
- 避免上位机异常退出后执行机构长时间保持输出

### 9.3 摩擦带

- 如果摩擦带有持续运行风险，也建议后续补 `timeout_ms`
- 若当前实现时间紧，可以先只做 `SET_OUTPUT` 和 `STOP`

## 10. 联调建议

建议按以下顺序联调：

1. `PING`
2. `ESTOP` / `CLEAR_ESTOP`
3. 底盘 `SET_VELOCITY` / `STOP`
4. 步进 `JOG` / `STOP`
5. 舵机 `SET_ANGLE`
6. 抽气 `SET_OUTPUT`
7. 摩擦带 `SET_OUTPUT`
8. 运送电机 `SET_OUTPUT`

## 11. 典型上位机接口示例

```python
robot.ping()
robot.estop()
robot.clear_estop()

robot.chassis.set_velocity(vx=300, vy=0, wz=0, timeout_ms=200)
robot.chassis.stop()

robot.stepper.jog(axis="z", direction=1, speed_sps=1200, accel_sps2=2500)
robot.stepper.stop(axis="z")

robot.servo.set_angle(servo_id=3, angle_deg=45.0, duration_ms=300)
robot.vacuum.set_output(pump_on=True, valve_on=False, timeout_ms=1500)
robot.friction.set_output(motor_mask=0x03, direction=1, pwm=40)
robot.conveyor.set_output(direction=1, pwm=50, timeout_ms=1200)
```

## 12. 当前版本落地范围

这份“竞赛最小版”建议作为当前实际开发目标。

当前只要求：

- 请求帧和应答帧
- 基本 CRC 校验
- 基本结果码
- 各模块最关键控制命令
- 底盘和部分执行机构超时保护

当前明确不做：

- 地址字段
- 事件上报
- 状态查询
- 转速查询
- 回零
- 目标位置控制
- 多节点扩展
- 参数持久化

后续如果比赛需求变化，再从完整版逐项补回即可。
